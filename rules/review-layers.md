# 지적의 3층

모든 검토(`review`, `check`, `build`의 작업 검토, `design` 비평)는 지적을 3층으로 나눠요.

## 지적 하나의 형식
- 무엇이 / 왜 틀렸나 / 무엇으로 바꾸나 / 근거(논문, 레퍼런스, 계산, 실행 결과).
- 근거가 없거나 막연한 지적("더 견고하게", "개선 여지")은 버려요.

## 1층 하드
- 틀렸거나, 사용자나 데이터를 해치거나, 완료 조건을 못 채운 것.
- 바로 고치고 무엇을 고쳤는지 보고해요. 못 고치면 그 일은 완료가 아니에요.

## 2층 권장
- 고치면 더 나아지는 것.
- 모아서 한 번에 물어요. 번호, 근거, 고치는 비용을 한 줄씩. 사용자가 고른 번호만 고쳐요.
- 답이 없으면 고치지 않고 진행해요.

예시:
```
고칠지 골라 주세요(번호, 없으면 그대로 둬요).
1. 빈 목록일 때 안내 문구가 없어요 — 신규 사용자가 첫 화면에서 막힘 — 10분
2. 표 숫자가 오른쪽 정렬이 아니에요 — 자릿수 비교가 어려움 — 5분
```

## 3층 자유
- 취향과 개성(강조색, 둥근 정도, 말투의 미세한 차이). 지적하지 않아요.

## 검토자에게 주는 규칙
- 과잉 지적 금지: 1·2층에 들지 않으면 쓰지 않아요.
- 검토를 맡길 때 "이건 지적하지 마"처럼 미리 판단을 주지 않아요. 판단은 결과를 받은 뒤 메인이 해요.
